# Session 批量管理与首轮自动标题设计

日期：2026-07-25

## 1. 背景

当前网页工作台存在四个相关问题：

1. 左侧会话列表只能逐个删除，清理多个会话成本高。
2. 新会话完成首轮对话后，标题只是规范化并截断第一条用户消息，没有结合首轮回答概括主题。
3. 中间输入区获得焦点时出现明显蓝色边框，与整体中性视觉不协调。
4. 右侧附件区底部横线和 Token 标题分隔线重复。

本次只修改会话管理、首轮标题生成和上述两处样式，不重构无关模块，不改变正常对话、工具调用、附件或工作区业务。

## 2. 目标与非目标

### 2.1 目标

- 左侧会话列表增加显式批量管理模式。
- 批量模式支持鼠标矩形框选、单击增减、全选、取消和批量删除。
- 删除前统一确认；部分失败时准确保留失败项。
- 新会话首轮成功完成后，由 LLM 根据首轮用户问题和 Assistant Final response 生成简洁标题。
- 标题生成失败时稳定回退，不影响首轮回复展示。
- 手动标题永远不被自动标题覆盖。
- 输入区聚焦态改为轻量中性样式。
- 删除附件区与 Token 区之间的重复横线。

### 2.2 非目标

- 不为 Store 增加事务或真正原子的批量删除。
- 不增加 Gateway 批量删除接口。
- 不重新生成旧会话标题。
- 不把 Thinking、工具日志或附件全文发送给标题生成调用。
- 不引入新的前端测试框架。
- 不改变现有单会话右键重命名和删除能力。

## 3. 左侧批量管理交互

### 3.1 进入与退出

- “最近会话”标题右侧增加“批量管理”按钮。
- 进入批量模式后，工具栏显示：
  - `已选 N 项`
  - `全选`
  - `删除`
  - `取消`
- `Esc` 和“取消”均退出批量模式。
- 退出时清空选择集合和框选矩形。
- 批量操作进行中禁用工具栏，防止重复提交。

### 3.2 选择行为

- 批量模式中的每个会话行显示复选标记和选中视觉状态。
- 单击会话行只切换选中，不切换当前对话。
- 鼠标在会话列表空白区域按下并拖动时显示半透明选择矩形。
- 矩形与可见会话行相交即选中该行。
- 小于移动阈值的手势不进入框选，避免普通点击抖动误触。
- 使用 Pointer Events 和 pointer capture；指针移出列表后仍能正常结束拖动。
- 框选只覆盖当前可见行，不实现拖至边缘自动滚动。
- 触屏和键盘用户通过会话行复选标记完成相同操作，不依赖框选。

### 3.3 删除流程

- 删除按钮仅在至少选择一项时可用。
- 点击后显示一次确认弹窗，明确待删除数量。
- 确认后，前端通过 `Promise.allSettled` 并行调用现有：

  ```text
  DELETE /api/v1/sessions/{session_id}
  ```

- 成功删除的会话从列表移除。
- 删除失败的会话保留在列表并继续保持选中。
- 若存在失败，页面显示失败数量和安全错误信息，不把部分成功误报为全部失败。
- 若当前会话被成功删除，关闭对应 SSE 和本地详情状态，然后选择剩余列表中的第一项。
- 若全部会话均被删除，复用现有创建会话流程创建一个“新会话”并选中。
- 单会话右键菜单继续可用；批量模式中不打开右键菜单。

## 4. 首轮 LLM 自动标题

### 4.1 触发条件

仅在以下条件同时满足时触发：

- 请求来源为 Gateway。
- Session 当前标题严格等于默认值“新会话”。
- 当前请求是该 Session 首个成功完成的对话。
- 首轮已经产生 Assistant Final response。

CLI、定时任务、失败或取消的首轮不触发。旧会话和已有自定义标题不处理。

### 4.2 标题输入与输出

标题生成调用只接收：

- 首轮用户问题。
- 首轮 Assistant Final response。

不接收 Thinking、工具输入输出、系统事件或附件原文。

标题提示词要求：

- 输出纯标题。
- 不解释。
- 不加引号。
- 不换行。
- 不超过 20 个 Unicode 字符。
- 概括首轮对话主题，而不是机械复制用户问题。

返回值仍执行以下防御性清洗：

- 合并空白和换行。
- 去除首尾常见引号。
- 去除常见 `标题：` 前缀。
- 空结果视为失败。
- 超过上限时截断并添加省略号。

### 4.3 时序

1. 主 Agent 完成首轮回答并持久化 Assistant 消息。
2. 流式 Final response 已经能在页面显示。
3. Runtime 调用独立标题生成器。
4. 标题成功或回退后，Runtime 完成该 Run 并持久化最终 Session。
5. 终态刷新取得新标题，更新左侧列表和聊天头部。

标题调用不阻塞已产生内容的显示，但会轻微延后 Run 的最终完成状态和后续排队请求。标题调用设置短超时，避免长时间占用 Session 顺序。

### 4.4 回退和覆盖规则

- LLM 抛错、超时、空结果或清洗后无效时，回退为规范化并截断后的首轮用户问题。
- 如果用户在标题生成完成前手动重命名，会话标题已不再是“新会话”，自动结果必须丢弃。
- 第二轮和后续请求不再触发自动标题。
- 标题调用的 Prompt 和 Completion Token 计入当前 Session Token 用量。

## 5. 代码边界

### 5.1 Runtime

新增独立标题生成模块，职责包括：

- 构造无工具的 `LLMRequest`。
- 调用现有 `LLMClient`。
- 应用超时。
- 清洗标题。
- 返回标题及 LLM Usage，或返回明确失败结果供调用方回退。

`RuntimeHost` 只负责：

- 判断首轮自动标题触发条件。
- 把首轮用户问题和 Final response 交给标题生成器。
- 合并标题调用 Token Usage。
- 在保存前再次检查标题仍为默认值。

Bootstrap 复用现有 LLM Client 构造并注入标题生成器。不复制 Provider 配置。

### 5.2 Web

`App.tsx` 增加批量模式、选择集合、框选矩形和批量删除状态。继续复用现有 API helper、单会话删除流程和会话选择逻辑。

纯几何判断和选择集合更新应保持为小型无副作用函数，避免 Pointer Event 代码与删除业务混合。

### 5.3 样式

- 输入区显式覆盖 `:focus` 和 `:focus-visible` 的蓝色 outline/box-shadow。
- `.composer:focus-within` 仅使用轻量中性边框和阴影。
- `.attachments` 去掉底部 `border-bottom`，同步减少多余的 `padding-bottom` 和 `margin-bottom`。
- Token 自身分隔线保持不变。

## 6. 错误处理

- 批量删除使用逐项结果，不假设全部成功。
- 删除过程中网络失败只影响对应会话。
- 当前会话删除后的 SSE 必须关闭，避免旧事件写入新会话。
- 标题生成异常不得使主 Run 失败。
- 标题超时不得无限延后队列。
- 标题输出始终作为纯文本保存，不解释为 Markdown 或 HTML。

## 7. 测试与验收

### 7.1 自动化测试

标题生成器单元测试：

- 正常生成。
- 合并换行和空白。
- 去除引号和标题前缀。
- 超长截断。
- 空输出、异常和超时回退。
- 请求不携带工具定义。

Runtime 测试：

- 首个成功 Gateway 对话生成标题。
- 输入包含首轮用户问题和 Final response。
- 标题调用 Token 正确计入。
- 手动标题不覆盖。
- 第二轮不重复调用。
- 失败或取消首轮不生成。
- 标题生成失败不使主 Run 失败。

现有测试：

- 完整非 live Python 测试。
- 前端 TypeScript 和 Vite 构建。

### 7.2 浏览器验收

- 进入和退出批量模式。
- 单击增减选择。
- 鼠标矩形框选多个可见会话。
- 全选、取消和 `Esc`。
- 删除确认。
- 删除当前会话。
- 全部删除后自动创建新会话。
- 人工模拟一个删除失败时，成功项移除、失败项保留。
- 首轮回复完成后列表和聊天头部出现 LLM 概括标题。
- 手动重命名不会被覆盖。
- 输入区聚焦不出现蓝色矩形框。
- 附件区与 Token 区之间只保留 Token 分隔线。
- 桌面和窄屏布局无新增遮挡或溢出。

## 8. 风险与控制

- 标题额外调用会产生少量费用和延迟：限制输入、输出长度并设置短超时。
- 用户内容可能尝试影响标题提示：使用独立 System 指令，并对输出做纯文本清洗。
- 并行删除可能部分成功：使用 `Promise.allSettled` 明确反馈，不伪装事务。
- 框选可能与点击冲突：只允许从列表空白处启动，并设置移动阈值。
- 工作区已有大量未提交修改：实现仅修改相关文件，提交时严格限定路径。
