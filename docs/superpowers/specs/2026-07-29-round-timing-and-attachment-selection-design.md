# 本轮附件取消与轮次耗时设计

## 目标

- 在右侧“本会话附件”区提供明确的“取消本轮选择”按钮。
- 在每个已完成助手回复上方显示本轮处理耗时，样式为紧凑的“已处理 23s”信息行。

## 非目标

- 不删除会话附件或附件本地内容。
- 不新增或修改 Gateway API、持久化模型和 Run 数据。
- 不展示小于 1 秒、缺少时长或尚未结束的轮次耗时，也不显示占位解释。

## 交互

### 右侧附件

- 现有附件行继续用于选择或取消选择单个附件。
- 当存在本轮已选附件时，标题区显示“已选 N”和“取消本轮选择”。
- 点击“取消本轮选择”清空 `selectedAttachmentIds`，不会发出网络请求，不影响附件文件和历史消息。
- 归档会话保持只读；取消选择按钮禁用。

### 轮次耗时

- Gateway 已返回每个 Run 的 `assistantMessageId` 与 `durationMs`。
- 前端按 `assistantMessageId` 将完成 Run 映射到对应助手消息，并在该消息组上方渲染耗时行。
- `durationMs >= 1000` 时显示，格式使用秒；否则完全不渲染。
- 流式回复进行中、失败或取消且没有助手最终消息时不新增耗时行。聊天顶栏的实时运行状态与计时保留。

## 实施范围

- `web/src/App.tsx`：构建消息到 Run 的查找、渲染耗时行、添加清空本轮附件选择的操作。
- `web/src/styles.css`：补充紧凑耗时行和附件标题操作的样式及键盘焦点状态。

## 验收

1. 右栏选中多个附件后，点击“取消本轮选择”会清空选择；附件仍保留在列表中。
2. 已完成且耗时至少 1 秒的助手回复上方显示“已处理 Ns”。
3. 耗时不足 1 秒、无时长或未完成的回复不显示任何耗时元素。
4. 附件上传、单项选择、发送请求、流式回复和归档会话只读限制不回归。
5. TypeScript 构建通过。

## 风险与处理

- 历史会话可能没有 `durationMs` 或 `assistantMessageId`；前端跳过显示。
- 一个助手消息未被任何 Run 引用时跳过显示，避免猜测轮次归属。
